# 모바일 지도와 탐색 개선

검토일: 2026-11-16. 기존 브랜드를 유지하는 제품 UI 개선이다. 사용자 행동 분석이나 전환율 데이터는 수집하지 않았으며, 아래 판단은 공식 제품 문서와 실제 화면 측정에 근거한다.

## 기존 화면 진단

- 청록 `#216D74`, 깊은 강 `#123D46`, 안개 `#F1F5F4`, 표면 `#FCFDFC`, 경계 `#DCE6E3`를 유지한다. 글꼴은 기존 Pretendard와 시스템 숫자 글꼴을 유지한다.
- 운동 / 기기 기록 / 통계 / 설정의 경로와 하단 메뉴 이름은 유지한다. 메타데이터, 로고, 인증 정책은 변경하지 않는다.
- 기본으로 펼쳐진 목표 패널이 지도 영역을 크게 가렸다. 기존 접기 동작은 시작 버튼까지 화면 아래로 밀어냈다.
- 더보기의 기록·설정은 하단 메뉴와 달리 로그인 유도 레이어를 추가했다. 로그인 여부에 따라 다른 전환을 사용하고, 정적 앱에서도 서버 기반 클라이언트 라우팅을 호출했다.
- 배포 웹에서는 게스트 로그인 레이어를 닫을 수 있었다. 모든 환경에서 터치 불능을 재현했다고 주장하지 않는다. 중복 차단 레이어와 정적 앱의 라우팅 불일치를 제거하고 반복 전환을 회귀 검증한다.

## 설계와 검토

`DESIGN_VARIANCE: 4`, `MOTION_INTENSITY: 2`, `VISUAL_DENSITY: 3`. 야외에서 한 손으로 조작하는 사용성을 우선한다. 기존 CSS와 Tailwind를 사용하고 새 디자인 시스템이나 장식 이미지를 추가하지 않는다. 모서리는 기존 규칙인 시트 28px, 주요 버튼 15px, 도구 13px를 유지한다.

```text
브랜드                    지도 도구

             지도

선택한 목표               목표 변경
지도 준비                 하이킹 시작
              시작
운동 / 기기 기록 / 통계 / 설정
```

내용은 왼쪽 정렬한다. 펼친 설정만 스크롤하고 시작 버튼과 탐색은 화면에 유지한다. 접힌 설정은 `hidden`으로 포커스와 터치에서도 제외한다. 스와이프 없이 버튼과 키보드로도 펼칠 수 있다. 설정을 줄인다는 이유로 시작 버튼까지 숨기는 기존 방식은 폐기했다. 추가 설명과 사진으로 채우는 랜딩 페이지 구성은 실제 지도 앱의 목적에 맞지 않아 적용하지 않았다.

통계와 설정은 더보기에서도 하단 메뉴와 같은 문서 이동을 사용한다. 로그인은 기존 인증 화면에서 처리한다. 정적 앱의 로그인 화면 복귀도 문서 이동을 사용한다. 검색과 더보기는 Escape로 닫는다.

게스트의 `AuthSessionMissingError`는 로그인하지 않은 상태로 처리하고, 다른 인증 오류는 그대로 전달한다. `getUser()`를 통한 사용자 검증은 유지한다. 기록 로딩 화면에도 홈 링크와 하단 탐색을 남기고, 정적 앱의 인증·기록 요청은 각각 10초 이내에 실패 상태로 전환한다. 느린 연결 때문에 다른 메뉴까지 사용할 수 없어지는 흐름을 방지한다.

설정의 온라인 상태는 브라우저가 준비된 뒤 반영한다. Node의 `navigator` 유무에 따라 서버 HTML과 첫 브라우저 렌더가 달라지던 hydration 오류도 반복 이동 검사에서 발견해 수정했다.

## 화면 측정

390×844 CSS px, 안전 영역 0px 기준으로 배포 전 화면의 패널은 상단 309px, 높이 470px였다. 개선한 정적 번들의 기본 접힌 패널은 상단 594px, 높이 185px다. 같은 화면 크기에서 패널 높이는 약 61% 줄었다. 이는 DOM 영역 측정이며 사용성 점수나 실제 기기 성능 측정값은 아니다. 320×568에서는 상단 318px, 높이 185px다.

## 검증 기준

- 320×568 / 390×844, 밝은 / 어두운 모드에서 접힌 패널 상단이 화면 높이의 50% / 60% 아래에 있어야 한다.
- 목표를 선택하고 접어도 선택한 목표와 시작 버튼이 남아야 한다.
- 더보기 기록 → 로그인 → 홈 → 더보기 설정 → 홈 → 하단 통계를 반복해도 다음 조작이 가능해야 한다.
- 정적 HTML 번들에서 외부 네트워크를 차단한 상태로 검사한다. Chromium과 CI WebKit은 실제 iPhone 실기기 검증을 대신하지 않는다.
- 기존 오프라인 GPS, 복구, 결과 저장 검증을 유지한다.
