# Android / 오프라인 전환

2026-11-14: 사용자가 Organic Maps와 같은 오프라인 산행 기능의 단계별 구현과 commit → push → PR → 검사 → merge를 승인했다. 웹 오프라인 기능은 유지하면서 Android 기반을 최신 main 위에 다시 통합한다. 기존 Android PR #2는 충돌하는 이전 구현이며 이번 작업의 출발점으로 일부 파일만 재사용한다. 실제 기기 검증과 자동 검증 결과는 구분한다.

각 단계는 최신 main에서 브랜치를 만들고 구현 → 검증 → commit → push → PR → 검사 확인 → merge 순으로 진행한다. 실패한 검사나 저장소 보호 규칙을 우회하지 않는다. 앱 기반 코드는 자동 검증 후 병합하되, 실제 GPS·화면 잠금·배터리는 실기기 결과 없이 지원 검증 완료로 표시하지 않는다.

| --- | --- | --- |
| 1 | 기존 웹 빌드 기준과 CI 확보 | 깨끗한 의존성 설치 후 프로덕션 빌드 성공 |
| 2 | Capacitor Android 앱과 로컬 웹 번들 | 웹·모바일 빌드, Android 컴파일, 기기 설치·화면 이동 |

## 설계 기준

- Android부터 진행한다. iOS는 Mac / Xcode 및 기기 검증 환경이 필요하다.
- 앱은 웹 자산을 패키지에 포함한다. 운영 사이트 URL을 WebView에서 여는 구성만으로는 오프라인 실행을 보장할 수 없다.
- 웹의 서버 렌더링·인증 콜백과 모바일의 정적 번들 경계를 분리한다.
- 위치 수집·저장은 화면 JavaScript 생명주기에 의존하지 않도록 한다. 백그라운드 콜백만 연결하고 저장을 화면에 맡기면 데이터 손실 가능성이 남는다.
- GPS 기록과 지도 다운로드, 오프라인 길찾기는 각각 별개의 기능이다.
- Android의 강제 종료 이후 자동 추적 재개는 보장하지 않는다. 사용자가 운동을 시작·중지할 수 있게 하고 실행 중 위치 수집 알림을 표시한다.

## 초기 환경 확인

- main과 origin/main은 동일한 커밋에서 시작했다.
- 사용자 로컬 변경 `.claude/settings.local.json`은 작업 커밋에 포함하지 않는다.
- Windows PowerShell의 실행 정책 때문에 npm.ps1 대신 npm.cmd를 사용한다.
- 초기 node_modules에는 실행 파일이 누락되어 npm ci로 복구한다.
- 초기 PC에는 JDK 17만 있고 Android SDK가 없다. Android 도구 체인과 기기 검증은 웹 빌드와 별도로 확인한다.
