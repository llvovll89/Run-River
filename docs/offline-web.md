# iPhone 웹앱 오프라인 기록

## 사용 순서

1. 인터넷이 연결된 상태에서 웹앱을 열고 **오프라인 실행 준비 완료**를 확인한다. iPhone 홈 화면에 추가했다면 홈 화면 앱에서도 한 번 온라인으로 열어 준비한다.
2. 거리·시간·인터벌 목표를 선택하고 운동을 시작한다. 데이터가 끊겨도 화면을 켜둔 동안 브라우저가 제공하는 GPS 좌표를 받아 거리와 이동 궤적을 갱신한다.
3. 지도 배경을 불러올 수 없으면 도로 지도 대신 이동 궤적을 표시한다. 지도 지역 다운로드와 오프라인 길찾기는 구현 범위에 포함되지 않는다.
4. 진행 중 기록은 기기에 저장한다. 탭을 닫거나 새로고침한 뒤 홈의 **기기 기록 · 진행 중인 운동 복구**에서 이어갈 수 있다. 복구 시에는 항상 일시정지로 시작하며, 중단된 동안의 시간·거리를 자동으로 기록했다고 간주하지 않는다.
5. 종료한 운동은 경로와 함께 **이 기기의 운동 기록**에 남는다. 게스트 기록은 기기에만 보관한다. 로그인 상태를 확인하고 시작한 운동은 원래 계정으로 연결됐을 때 통계를 서버로 업로드한다. 경로 좌표는 현재 서버 테이블에 컬럼이 없어 기기에 보관한다.

## 보존과 동기화

- 활성 운동 `rr_active_run`, 완료 운동 `rr_local_results`, 업로드 대기열 `pendingRunRecords`는 localStorage에 저장한다. 기기 저장 공간 부족·손상 시 저장 실패를 표시하고 기존 기록을 지우지 않는다.
- 종료 시 기기 저장 성공을 확인한 뒤 활성 기록을 정리한다. 이후 pagehide 이벤트가 완료 운동을 다시 활성 기록으로 저장하지 않게 한다.
- 각 운동에 UUID를 부여한다. 서버 INSERT 응답이 유실되어 재시도되더라도 같은 기본 키를 사용하며, 이미 존재하면 RLS가 허용하는 기존 행을 조회한다. DB 스키마·정책 변경은 없다.
- 업로드 payload에 원래 user_id를 넣고 검증된 현재 사용자와 비교한다. 다른 계정, 게스트, 소유권 정보가 없는 기존 대기 기록은 자동 업로드하지 않는다. 계정 변경 중 요청이 나가더라도 서버 RLS가 소유권을 검사해야 한다.
- 큐가 300건에 도달하면 새 큐 삽입을 거절한다. 오래된 기록을 밀어내지 않으며 완료 기록의 기기 복사본은 유지한다.
- 서비스 워커는 공개 화면 `/`, `/running`, `/result`, `/local-history`와 빌드 자산만 저장한다. 인증·서버 기록·설정·API·RSC 응답을 캐시하지 않는다. 네트워크 복귀 시 운동 화면을 자동 새로고침하지 않는다.
- 새 버전은 사용자 업데이트 동작 후 활성화한다. 오프라인 자산은 캐시 삭제 없이 유지한다.

## 검증 명령

```powershell
npm.cmd ci
npm.cmd run test:unit
npx.cmd playwright install chromium webkit
npm.cmd run test:offline
npm.cmd run build
```

`test:offline`은 전용 가짜 API 설정으로 빌드한 뒤 실제 프로덕션 Next 서버를 실행한다. 테스트 API는 로컬 HTTP 서버에서 제공해 서비스 워커와 두 브라우저 엔진에 동일하게 적용되며 운영 계정·DB에 접근하지 않는다. 테스트 후 개발자가 실제 설정으로 실행하려면 `npm run build`를 다시 실행한다.

- 단위 테스트: 세션 저장소 소실 후 복구, 기존 기록 호환, 손상·저장 공간 부족, 경로 보존, 중복 큐, 큐 용량, 재시도·백오프.
- Chromium 및 iPhone 화면 설정의 WebKit: 준비 후 오프라인 재실행, 모의 GPS 갱신, 새 탭 복구, 일시정지 복구, 저장 공간 부족 후 재시도, 완료 기록 재열기, 비공개 화면 캐시 제외, 다른 계정 업로드 차단, 서버 응답 유실 후 중복 없는 재시도.
- GPS는 네트워크 에뮬레이션과 독립적인 결정적 콜백으로 주입한다. 물리적인 GPS 수신·iOS 전원 관리·홈 화면 앱의 OS 동작을 테스트했다고 주장하지 않는다. Windows WebKit의 Playwright 위치 모의 구현은 네트워크 차단 시 watchPosition 갱신에 제약이 있어 앱의 콜백 처리를 직접 검증한다.

## 실제 환경의 한계

웹앱은 화면 잠금·앱 전환 중 연속 추적을 보장하지 못한다. 브라우저 데이터 삭제·저장 공간 정리·OS의 사이트 데이터 제거 시 기기 기록과 캐시도 사라질 수 있다. 첫 실행부터 인터넷이 전혀 없는 상태에서는 앱 파일을 준비할 수 없다.

현재 로컬 환경의 Supabase 연결은 이전 확인에서 DNS ENOTFOUND로 실패했다. 자동 검증은 가짜 서버로 수행하며, 실제 로그인·운영 DB 저장 여부는 별도 연결 확인이 필요하다.

2026-11-14 Android 구현을 재개했다. 최신 [네이티브 구현 범위](native-roadmap.md), [오프라인 지도](offline-maps.md), [하이킹](hiking.md)을 따른다. 기존 PR #2는 최신 기반 PR #5로 대체하고 닫았다. 웹의 화면 잠금 제약은 그대로이며 Android 실제 기기 검증은 별도로 필요하다.
